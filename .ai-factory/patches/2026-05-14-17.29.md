# Telegram back button cancels progress and returns to quality selection

**Date:** 2026-05-14 17:29
**Files:** src/adapters/telegram/menus/download-menu.ts, src/adapters/telegram/menus/download-menu.test.ts, src/server/index.ts
**Severity:** medium

## Problem

Pressing the Telegram `Назад` button while a download was already running only showed the popup `Задача выполняется.`. The user could not return to the quality selection menu from the progress view, and the active download continued.

## Root Cause

The progress-state root menu rendered `Назад` and `Отмена`, but only `Отмена` called the cancellation path. `Назад` was deliberately guarded as a no-op for busy sessions, even though the menu session already preserved `returnState` and `returnSelectedContainer` when the download started.

## Solution

Changed the progress `Назад` handler to cancel the active job and restore the saved selectable menu state. The restore path clears `activeJobId`, progress sizing, and return-state fields, then redraws the menu message with the quality/container/audio/root markup that matches the saved return state.

Extended the server cancel handler with a `preserveSession` flag so the back-navigation cancellation aborts the job without running terminal progress cleanup that would delete the menu session. Normal `Отмена` still performs terminal cancellation and removes the menu session.

Added `[FIX]` logging around progress-back cancellation, restore success/failure, and server-side cancellation with `preserveSession`.

## Prevention

- For menu actions that can interrupt progress, test both the job cancellation side effect and the restored menu state.
- Keep terminal cancellation and navigation cancellation separate: terminal cancellation may delete the menu session, while navigation cancellation must preserve and redraw it.
- Reuse stored `returnState` and `returnSelectedContainer` whenever a progress view needs to return to a selectable menu.
